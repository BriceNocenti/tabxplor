Micro (in-suite test-display-grammar.R): display_primary() x20 on 1e6 no-composite cells = 0.22s
  -> ~11 ns/cell for the gate (one fixed grepl + any()).

* The COMPOSITE row is informational only: on the baseline a "{pct} (n={n})" hand-written into the
  display field is NOT parsed (renders the primary), so 0.655s; AFTER it does the real 2-field render
  (2 sub-format() calls + paste), so 2.455s. This cost is paid ONLY when a composite is actually used
  (opt-in tab(display=)), never on a normal table.

VERDICT -- Solution 2 confirmed (ship as-is; no Solution-3 dedicated fast tokens needed).
  The {} template lives in the per-cell `display` FIELD, resolved by the gated display_primary().
  On NO-composite tables (the vast majority) the whole display/export pipeline is UNCHANGED:
  build/print/tab_md/tab_kable/tab_xl show no measurable difference. The only movement is a ~3%
  (+0.02s over 20 reps) bump on an ISOLATED format() of a 200k-cell column -- within system.time
  resolution and dwarfed by the render work in every real exporter. The gate is negligible "for
  nothing"; the composite cost is opt-in. => keep the single {} code path.
