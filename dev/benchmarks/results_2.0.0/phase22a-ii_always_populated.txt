WHAT WAS BOUGHT. Every model column now stores its adjusted prediction and its additive marginal
effect whether or not the cell prints them, so `display` is a pure post-hoc property: choosing a
layout triggers no computation, changes no number, and set_display() on a finished table gives the
same table as asking at build time (which is also what lets jamovi repaint without refitting).

WHERE THE TIME GOES.
  * the COEFFICIENT path pays a full point-estimate g-computation sweep it never ran before (HEAD ran
    one only when `display` asked for a fold). No delta method, no jacobian, no dependency.
  * the RATIO-marginal path pays a SECOND sweep, for the additive twin: a marginal ratio is not an
    average of differences, so it cannot be re-derived from the one the estimate came from.
  * a factor level's additive contrast is DERIVED from the two adjusted predictions rather than taken
    from the sweep's own contrast -- exact (averaging commutes with an additive contrast) and
    reference-invariant, which is what keeps jamovi's digest path a cache hit on a reference change.

NOT PAID. The crude columns cost less than before (one fmt() call per effect instead of two), and
format() / a tab() build are unchanged within noise.
