2b. PoC — byte-identity PROVEN (identical(), the 9d method), then measured
================================================================================
Two candidates vs the REAL live functions, across 26 shapes
  (factor / mixed / mean col_vars x comp tab/all x 0-2 tab_vars x unweighted/weighted x a 2x2 Yates):

  fast_chi2_compute_test()  identical(): 26 / 26   GREEN
  fast_is_a_mean()          identical(): 26 / 26   GREEN

  Byte-identity landmine found + resolved in the PoC: agg_chi2/agg_anova DROP degenerate
  subtables (n<2 / no valid cells); the live code recovers them as all-NA rows via
  distinct(long)+left_join(engine). A naive "build rows from the engine output" candidate LOSES
  them (8/26 mixed+tab_vars fails). The correct rewrite rebuilds the FULL (table_id,cv,subtab)
  tuple set from the inputs and match()es the engine results (NA where dropped) -- i.e. it must
  RE-IMPLEMENT the distinct+left_join shape in base-R. => not a simplification, just faster primitives.

MEASURED speedups:
  is_a_mean         : 0.00276 s -> 0.00041 s   6.78x   (isolated)
  chi2_compute_test : 0.0793 s  -> 0.0732 s    1.08x   (isolated, chunky shape -> engine-dominated)
