KEY CORRECTIONS to the plan's cost model:
1. The col_var full_join is CHEAP: reduce/full_join = 0.9%, vec_slice = 1.5% (§5 Part 2), and a
   direct probe measured full_join at ~1.5 ms/join. bind_cols is 20x SLOWER (name-repair on the
   duplicated "Total" columns). => The JOIN IS NOT THE TARGET (the plan's L2 focus was misplaced).
2. The reconstruction is PERVASIVE dplyr-over-fmt (mutate/across/transmute/is_* each vec_restore
   every fmt column), NOT localized to slice/join. new_rcrd 12.6% is mostly the REBUILDS, not the
   one-time materialize (the materialize-once floor is 0.5%, §5 Part 3).
3. The LEAF TAIL is cheap on the common path (default total_names make the renames no-ops; column
   renames/reorders don't row-reconstruct) -- porting it banks little.
4. tab_apply_tests / tab_chi2 (20%) is the SINGLE BIGGEST recoverable chunk. Isolated tab_chi2
   profile (400x, 8x5 built table, 43.6 ms/call): is_totrow.data.frame 34.6% (called ~5x, each
   O(cols)), dplyr::transmute 33.6 / select 26.0 / mutate 26.5 (dplyr-over-fmt), the helpers
   tab_add_totcol_if_no 19.7 / tab_match_groups_and_totrows 19.2 / tab_match_comp_and_tottab 17.2,
   agg_chi2 17.0 (the actual vectorised chi2 math). The tabs[!is_totrow,] slice alone = 4.0 ms.
   => tab_chi2's cost is REPEATED is_totrow/is_totcol scans + dplyr-over-fmt group-matching, only
   partly the record rebuild. The carrier (plain fields + precomputed row/col masks) removes both.

IMPLICATION for the 9b-3 staging: the win requires the carrier to span the WHOLE within-row_var
pipeline (leaf materialize deferred + tab_apply_tests + assemble on plain fields), dominated by
making tab_chi2/tab_ci read plain fields with row/col masks computed ONCE. There is no cheap
subset; the join is not worth reimplementing (keep the record full_join / materialize around it).
