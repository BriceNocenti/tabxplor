=== Phase 8 measured gate — why build-only dispatch caps at ~1.15-1.3x ===
Workload: tab(d, 12 row_vars, c(race, tvhours), wt=w, pct="row", color="diff", chi2=TRUE)
N = 30 000 rows | Rprof, 6 builds, interval 0.004 | R 4.5.1, 8 physical cores

Stage breakdown (total.pct of one serial tab() build):
  tab_transform      53.2%   -- contains BOTH the parallelisable build AND the serial tests+join
    new_fmt          18.3%   [PARALLELISABLE: fmt record assembly, in tab_plain + tab_num]
    tab_plain        12.6%   [PARALLELISABLE: pct/diff/color + new_fmt, factor leaf]
    tab_num           8.1%   [PARALLELISABLE: derive stats + new_fmt, numeric leaf]
    tab_apply_tests  18.4%   [SERIAL on main: chi2 + ci]
  tab_assemble       34.7%   [SERIAL on main: level-drop, totals, p-value lines, merge]
    tab_compact      11.4%   [SERIAL: the output_list=FALSE merge -- an inherent gather]
  tab_chi2          ~31.8%   [SERIAL: factor chi2 (tests) + numeric ANOVA]
  tab_aggregate      10.6%   [SERIAL on main: the O(N) scans -- num_moment_scan 9.1%, factor .fine]
  tab_setup/prepare   1.0%

PARALLELISED today (tab_build_rowvar = tab_plain + tab_num fmt build): ~25-30% of total.
SERIAL by design (aggregate + tests + assemble/merge): ~70%.

Amdahl with p=0.28, W=8:  1/(0.72 + 0.28/8) = 1.32x ceiling  -> observed 1.15-1.19x (minus
ship/collect overhead). Matches run_parallel.R (phase8_survey.txt).

Contrast: the §26 PoC got ~3.3x because it dispatched WHOLE independent per-table tab() calls
(each worker ran its own aggregate + build + chi2 + per-table assemble; no shared vectorised
chi2, no merge). Phase 8 deliberately keeps aggregate + tests (Phase 3b vectorised) + assemble
on main for byte-identity-by-construction -> only the O(cells) fmt build parallelises.

Projected if more moves onto the worker (per-row_var, still gather+merge on main):
  + fold tests into worker  -> p~0.56 -> ~1.9x (W=8)
  + fold aggregate too      -> p~0.66 -> ~2.4x
  + fold per-table assemble -> p~0.80 -> ~3x (= §26 whole-pipeline dispatch)
Each step needs byte-identity re-validated (per-row_var chi2 == the stacked agg_chi2; test-tibble
concat order; global duplicated_levels rename stays on main regardless).

=== Byte-identity ceiling (proto_independence.R) ===
An independently-built single-row_var tab() is NOT byte-identical to its slice of the integrated
multi-row_var build: the total column is "Total_denom" (multi) vs "Total" (single) -- a cross-row_var
coupling in tab_assemble's lone-total rename-back (identical everywhere else, all na modes).

=> tab_assemble MUST stay on main for byte-identity. Movable to workers: aggregate (~10%) + build
(~25%) + tests (~31%) = ~66%. Serial floor: rename/join (~1%) + assemble (~35%, incl. merge 11%).
Byte-identical dispatch ceiling: p~0.66 -> ~2.4x at W=8 (NOT 3x).

True ~3x (§26 PoC) needs assemble on workers too, which requires DECOUPLING the total-col naming
(a small cosmetic golden change: "Total_denom" -> "Total" in multi-row_var mixed-col_var tables).
