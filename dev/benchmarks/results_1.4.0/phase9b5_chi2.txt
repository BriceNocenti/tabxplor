HONEST NOTES:
- Increment 1 (the chi2 TEST) gave NO measurable win: a clean git-stash A/B on a 40x15 table was
  0.1000 s == 0.1000 s (old == new). The dev/..._phase9b §6 "tab_chi2 = 20%" was an ISOLATED
  tab_chi2 with the DEFAULT calc = c("ctr","p","var","counts") -- i.e. the CONTRIB writes, NOT the
  calc = "p" test the pipeline runs. On color = "diff" there are no contrib writes, so the test
  marshalling is cheap and carrier-izing it is invisible. Its value is code clarity + the no-op
  removal + scaling on very large tables, not a demonstrable speedup here.
- The REAL tests-boundary costs are the WRITES: contrib +97% vs a plain build (recovered here,
  -41%), and the ci write-back +55% (NOT yet touched -- increment 2). The read/write staging holds:
  the WRITES are where the O(cells) fmt reconstruction lives.
- Approach: NOT a fmt_unwrap/fmt_wrap carrier round-trip but a precompute-then-single-write (real
  setters, fewer reconstructions than a carrier, no set_* reproduction risk). var_contrib is PER
  SUBTABLE (the old writes were grouped mutates); the write runs ungrouped then restores grouping.
