Phase 10h openxlsx2 tab_xl benchmark (min of 3, gss_cat n=21483; R 4.5.1, openxlsx2 1.27)

single table (marital x race, colour + chi2): 0.34 s

list of 12 tables (row_var x c(marital, race), colour + chi2):
  sheets = "tabs"   : 5.83 s
  sheets = "auto"   : 5.81 s
  sheets = "unique" : 5.78 s          -> sheet layout is irrelevant

scaling (sheets = "auto"): 4 -> 1.67 s (0.42/tab), 8 -> 3.59 s (0.45/tab), 12 -> 5.73 s (0.48/tab)
  -> LINEAR in #tables, ~0.45 s/table. NOT quadratic-on-one-sheet.

parallel (list of 12, 6 workers): 5.08 s vs 5.54 s serial -> 1.09x speedup.

INTERPRETATION
- The cost is openxlsx2's FIXED per-style-call overhead (~40 wb_add_* calls/table, ~11 ms each),
  NOT per-cell work: tiny gss_cat tables already cost ~0.45 s each. This is the known openxlsx2
  styled-write slowness (decisions doc 21).
- The plan CPU (format codes + colour channels + font tuples + geometry) is only ~8% of the total;
  the openxlsx2 WRITE (serial, on the main process, mutating one workbook) is ~92%.
- Therefore parallel= is Amdahl-capped at ~1.09x for tab_xl (1/(0.92 + 0.08/6) ~= 1.07). It is
  byte-identical to serial and harmless, but does NOT deliver a real speed-up for Excel export
  (unlike ~2.4x for tab() building, where the per-row_var work IS the cost). A gain would need a
  plan-CPU-bound export, which does not occur while the openxlsx2 write dominates.

STYLES-MANAGER WRITE OPTIMIZATION (DONE 2026-07-12)
- Replaced the ~40 separate wb_add_font/fill/border/align passes per table with a PRECOMPOSE: build
  each cell's full style (font+fill+border+alignment) in one per-cell grid (xl_build_styles), group
  into the fewest DISTINCT styles, register deduped fonts/fills/borders + a composed cell xf ONCE, and
  apply by id with set_cell_style over each style's coalesced dims (xl_apply_styles). numFmt stays a
  separate grouped wb_add_numfmt pass that merges cross-aspect.
- Result (same fixtures): single table 0.34 -> 0.24 s (~1.4x) ; 12 tables 5.5 -> 3.0 s (~1.8x).
  Fidelity verified (header bold+border+align, data font_num+numfmt+valign, diff palette font colours,
  fill on bg-coloured cells). Full suite green, no golden regen.
- Micro-benchmark that drove it: 40 set_cell_style (pre-registered) = 0.07 s vs 40 wb_add_font =
  0.12 s (1.7x cheaper/call); register+apply 40 xfs = 0.12 s vs 40 separate wb_add_* = 0.23 s (1.9x).

PARALLEL-WRITE-MERGE (studied 2026-07-12, NOT pursued -- maintainer chose styles-manager only)
- Alternative: each worker builds its sheet in its OWN wb, main merges via wb_clone_worksheet(from=).
  Works ONLY via a save->wb_load->clone workaround (clone_worksheet fails on in-memory borders, the
  same openxlsx2 styles bug; loading normalizes it). All styles survive. ~2.5-3x for large batches.
  BUT batch-only (no single-table gain), adds mirai + temp-file + merge machinery, and once the
  styles-manager makes the write cheap the merge tax (~0.06/sheet) caps the extra gain. Dominated by
  the styles-manager approach; not implemented.
